# Login setup

1. Run `db/migration_users.sql` once in MySQL Workbench, with `organ_allocation` selected.
2. Ensure `.env` contains the existing DB settings and a long random `SECRET_KEY` value.
3. Activate the project virtual environment and install requirements if needed: `pip install -r requirements.txt`.
4. Create the first administrator interactively: `python create_admin.py`. Choose a username and a password of at least 10 characters. The password is stored as a salted hash, not plain text.
5. Start the app with `python app.py`, open `http://127.0.0.1:5000`, and sign in.

Roles:
- `admin`: full dashboard access, scoring-policy changes, and patient record management.
- `coordinator`: same project operations as admin, intended for allocation review.
- `hospital`: can access the dashboard and register patients, but cannot change scoring policy or edit/delete patient records.

To add another account, use the same `create_admin.py` script for an administrator. For coordinator/hospital accounts, use the SQL user table with a password hash generated by Python's `werkzeug.security.generate_password_hash`; do not insert plain-text passwords.

This is an academic prototype login, not production-grade identity management. Before deployment, use HTTPS, a production secret key, CSRF protection, rate limiting, password reset, and stronger account administration.
